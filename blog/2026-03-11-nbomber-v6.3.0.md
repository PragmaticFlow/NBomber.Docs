The NBomber Studio v0.6.1 primarily brings several new capabilities for NBomber Studio. To simplify deploying NBomber Studio on Kubernetes, we’ve also released Helm charts for both TimescaleDB and NBomber Studio. NBomber Studio uses TimescaleDB as its primary storage for load test metrics. 

<!--truncate-->

## NBomber Studio improvements
The new v0.6.1 release introduces several powerful capabilities: Run Comparison, Trend Analysis, Exporting HTML report and Session Stopping.

With these additions, NBomber Studio is evolving beyond being just a UI for NBomber metrics into a full-fledged load testing platform. We are also working on the upcoming Load Testing in Kubernetes feature, which we expect to release in March or April.

### Authentication enabled by default
Starting with this release, NBomber Studio by default enebles authentication. You can configure authentication settings to add new members, disable auth entirely, and more. We don't store any credentials ourselves — you can also enable OIDC for external identity providers.

### Compare Runs
Compare Runs lets you select up to five load test sessions and compare them across multiple dimensions — latency, throughput, status codes, and more. You can quickly identify differences through percentage comparisons or explore detailed comparison charts for deeper analysis.

### Trend analysis
Trend analysis is particularly useful for teams that want to track load test performance over longer periods, such as several months or even a full year. You'll see a degradation curve based on load test metrics summarized per day and plotted across the entire period.

### Stopping session
Sometimes you may start a load test and later decide to stop it to adjust settings or investigate an issue. Now you can simply select a session and click Stop. 
:::info
This feature requires NBomber v6.3 and TimescaleSink v0.12.0 or later.
:::

### Download HTML report
Sharing load test results previously required storing generated HTML reports separately. Now you can directly download an HTML report from NBomber Studio using the **Download HTML Report** option for any completed session. 
:::info
This feature requires NBomber v6.3 and TimescaleSink v0.12.0 or later.
:::

### Helm charts
We’ve published two Helm charts to simplify Kubernetes deployments:

- A TimescaleDB (Community Edition) chart for running a single-node database used by NBomber Studio
- An NBomber Studio chart for deploying a single-node instance of the platform

These charts make it much easier to set up NBomber Studio in Kubernetes environments.

## What's next

We are actively working on several new features and projects:

### Load Testing in Kubernetes
We are finishing work on a highly anticipated feature for NBomber Studio: **Load Testing in K8s**. This will allow you to create and deploy load tests directly to Kubernetes from NBomber Studio, without requiring additional CI/CD jobs. We expect this to be released in late March or April.

### NBomber.YCSB
We have completed the initial version of [NBomber.YCSB](https://github.com/PragmaticFlow/NBomber.YCSB), a port of the Yahoo Cloud Serving Benchmark (YCSB) that lets you generate popular synthetic workloads against your database and evaluate how well it handles load. The release is coming this or next week. Contributions are welcome - we have many ideas planned and believe this project will bring significant value to the .NET community and beyond.

### SignalR plugin
We are also close to finishing the SignalR plugin for NBomber, which will allow you to write scenarios that interact with SignalR applications. The release is coming soon.

### LargeDataFeed package
We're making progress on the LargeDataFeed package, which extends NBomber's ability to work with very large files in your tests. The current DataFeed implementation keeps all data in memory, which can be limiting when working with very large datasets. LargeData Feed is designed to solve this by enabling efficient processing of large files without exhausting RAM.
